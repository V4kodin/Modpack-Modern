# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

TerraFirmaGreg-Modern — a Minecraft 1.20.1 Forge modpack (fusing TerraFirmaCraft + GregTech Modern). This is **not** a compiled application; it's a curated collection of mod configs, datapack/resourcepack overrides, and KubeJS scripts that are packaged into a distributable modpack via [Pakku](https://juraj-hrivnak.github.io/Pakku/home.html). There is no build step to "compile" — the closest things to CI/tests are KubeJS linting and the Pakku packaging workflow.

## Repo layout

- `pakku.json` — mod list, per-mod `side` (`CLIENT`/`BOTH`/server-only), and which top-level folders (`config`, `defaultconfigs`, `kubejs`, `tacz`) are shipped as overrides.
- `pakku-lock.json` — resolved/locked mod versions (generated by Pakku, not hand-edited).
- `pakku.jar` — the Pakku CLI tool, committed to the repo and used by CI to build/diff releases.
- `config/`, `defaultconfigs/` — per-mod configuration files (TOML/JSON/etc.) shipped with the pack.
- `kubejs/` — all custom scripting/content additions (the actual "code" of this repo). See below.
- `tacz/` — gun/weapon data for the TACZ mod.
- `.pakku/` — per-platform override folders (`docker-overrides`, `multimc-overrides`, `server-overrides`).

## KubeJS architecture (`kubejs/`)

KubeJS scripts run in **one shared global scope per script type** — there is no `import`/`require`. Each per-mod file defines a top-level function (e.g. `const registerAE2Recipes = (event) => {...}`), and that function is invoked from a central aggregator script:

- `kubejs/startup_scripts/main_startup_script.js` (`// priority: 100`) — wires registry events (items, blocks, fluids, GTCEu materials/machines/recipe types, etc.). Runs once at game startup.
- `kubejs/server_scripts/main_server_script.js` (`// priority: 1`) — wires tags, TFC data events, loot table modifiers, and `ServerEvents.recipes` for every integrated mod. Runs on every `/reload`.
- `kubejs/client_scripts/main_client_script.js` — client-side entry (tooltips, JEI/EMI). Runs on client resource reload (`F3+T`).

**When adding a new mod integration or content file**: create it under the appropriate `server_scripts/<mod_name>/`, `startup_scripts/<mod_name>/`, or `client_scripts/` folder, define its `registerXxx(event)` function(s) at top level, then add a call to that function from the relevant aggregator (`main_server_script.js`, `main_startup_script.js`, or `main_client_script.js`). Forgetting the aggregator call means the code never runs.

Per-mod folders are further split by domain, e.g. `recipes.js`, `tags.js`, `data.js`, `loot.js`, `events.js` — follow this convention for new files rather than dumping everything in one file.

- `kubejs/assets/` acts as a resource pack (client textures/models/lang).
- `kubejs/data/` acts as a datapack (loot tables, recipes as JSON, etc.).
- `kubejs/config/` is KubeJS's own config storage.

### Linting / formatting (kubejs/)

```bash
# Install once (from repo root or kubejs/)
npm install --prefix kubejs

# Lint
npm run lint --prefix kubejs
npm run lint:fix --prefix kubejs

# Format (Prettier)
npm run format --prefix kubejs
npm run format:check --prefix kubejs
```

**Do not run Prettier or the linter over an entire file.** Only format/lint the lines you actually changed (VS Code "Format Selection", not "Format Document") — running it over a whole file makes the diff unreviewable and such PRs get rejected, unless a team member explicitly approves a full-file pass.

TypeScript type-checking is opt-in: install deps, run ProbeJS to generate types, then set `"noCheck": false` in `kubejs/tsconfig.json` (default is `true`/off).

## Git workflow

- `main` — stable, released version. Requires Project-Lead approval to merge.
- `dev` — active development branch; PRs should target this. Requires two Modern-Team approvals.
- `feature/*` / `bugfix/*` — branch from `dev`, merge back into `dev`.
- PRs are merged via Squash and Merge.
- Config files are frequently auto-rewritten by mods on launch — before committing a changed config, check whether *you* intentionally changed it or the game just rewrote it; don't commit incidental config churn.

## CI (`.github/workflows/build.yml`)

Triggered on push to `dev`/`main` when `.pakku`, `config`, `defaultconfigs`, `kubejs`, `tacz`, `CHANGELOG.md`, `pakku-lock.json`, or `pakku.json` change. Uses the committed `pakku.jar` to diff `pakku-lock.json` against the previous tag (producing a mod changelog) and drives the release/build process. This is not something contributors normally run locally — local iteration is done by symlinking a dev `kubejs` folder into a PrismLauncher instance (see `.github/CONTRIBUTING.md` for the full setup) and testing in-game.
